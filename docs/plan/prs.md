# Happy build plan: pull requests

Every PR is a branch off `main`, small, self-contained, mergeable alone. Commit often inside a PR with real messages.
Branch name = `pr/<nn>-<slug>`. Each PR description: what, why, how to verify (3 lines).

Conventions for all code PRs (read `docs/plan/spec.md` first):
- Code lives in `app/happy/` (flat package; imports like `from tools.k8s_read import ...`, matching the generated `main.py`).
- Python 3.12, `uv` for env (`cd app/happy && uv sync --extra dev`), `pytest` for tests in `app/happy/tests/`.
- Config only via `config.py` `Settings` (pydantic-settings, reads `.env`). Never read `os.environ` elsewhere.
- Every tool is a Strands `@tool` with a one-paragraph docstring the model will read. Return plain dicts/strings, never raise on "not found"; return `{"ok": False, "error": ...}`.
- No secrets in code or in git. `.env` is gitignored.
- Models: `Settings.model_orchestrator` (Sonnet 5) and `Settings.model_specialist` (Haiku 4.5).
